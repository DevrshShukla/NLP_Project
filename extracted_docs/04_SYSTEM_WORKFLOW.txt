1. Purpose and Conventions
This document defines how data and control move through Study Topic Extractor for each user-visible
flow. Stage names match the pipeline modules in the NLP/AI Specification. Flows marked (P2) are
Phase 2.
Term
Definition
Analysis
One execution of the pipeline on one text with one configuration. Produces an Analysis Result.
Topic
A ranked study concept (word or phrase) with score, priority, summary, keywords.
Keyword
A distinctive term or phrase used for scanning vocabulary; topics may be keywords but not all
keywords are topics.
Score
Importance value 0 to 100 computed from weighted signals.
Priority
HIGH, MEDIUM or LOW derived from Score using configurable thresholds.
Study Roadmap
The complete structured output shown on the Results page.
Extraction quality
0 to 1 estimate of how much readable text a PDF yielded.

3.1 Rules
  The upload endpoint returns extracted text, page count and quality; it does not analyze. This lets
the user preview and lets Flow 1 run unchanged. The frontend may auto-continue when quality >=
0.5.
 Extraction quality: quality = readable_pages / total_pages where a page is readable if it has at
least 50 characters and at least 60% alphabetic characters after cleaning.
 Quality < 0.5 but > 0: return text with warning LOW_EXTRACTION_QUALITY; UI shows a dismissible
banner suggesting OCR (P2) or pasting text.
 Quality = 0 or no text: MVP returns NO_READABLE_TEXT. Phase 2 with ENABLE_OCR=true attempts OCR
at 200 DPI on pages without text, capped at 50 pages, then re-scores.
 Encrypted PDF: PASSWORD_PROTECTED_PDF. The product never asks for or stores PDF passwords in
MVP.
 Page or text limit exceeded: DOCUMENT_TOO_LARGE. Suggest splitting the document.
 Temporary data: PDF bytes are held in memory and released when the request ends. (P2,
authenticated save: bytes go to private storage.)

6.1 Retry Behavior
  Automatic: GET requests retry up to 2 times with exponential backoff (500 ms, 1.5 s) on network
errors or 502/503/504. POST analyze, upload and export are not retried automatically.
 Manual: every error state offers Retry that re-sends the original payload held in memory.
 429: the client waits for Retry-After seconds before re-enabling the button.
 Idempotency: analysis is deterministic and cacheable, so repeating a request is safe.

9. Acceptance Criteria
 1. Each flow behaves as specified for success and each listed failure.
2. Errors use the catalog messages exactly.
3. Cancel in Processing State aborts the network request within 200 ms.
4. PDF flow never writes user files to disk in MVP.
5. CSV export neutralizes formula injection.
6. Repeated identical analysis requests return identical topics and scores.
