1. Overview and Design Principles
The NLP layer converts raw study text into ranked, explainable topics. It is classical NLP first: spaCy
for linguistic analysis, scikit-learn for TF-IDF and clustering, and (Phase 2) Sentence Transformers for
semantic signals. No LLM is required anywhere in the core pipeline.
  Deterministic: no randomness in scoring. Clustering uses fixed random_state=42. Ties are broken by
occurrences then alphabetically.
 Explainable: each topic exposes its component scores (tfidf, frequency, position, semantic).
 Configurable: weights, thresholds and limits come from configuration, never from constants inside
code.
 Graceful degradation: if a Phase 2 stage is unavailable, the pipeline continues and adds a
warning.
 Versioned: every result carries pipeline_version; changing any algorithm or default bumps it.

2. Text Preprocessing
2.1 Order of Operations
 1. Normalization: Unicode NFKC; replace non-breaking spaces; normalize quotes, dashes, ellipsis;
remove null and control characters (keep \n, \t).
2. Noise removal: strip URLs, e-mail addresses, page markers (Page 3 of 20), repeated
header/footer lines (> 60% of pages), table-of-contents dot leaders, isolated page numbers.
3. Whitespace handling: collapse runs of spaces; join hyphenated line breaks (classi-\nfication to
classification); convert single newlines inside paragraphs to spaces; keep blank lines as paragraph
breaks.
4. Duplicate removal: drop exact duplicate sentences (case-insensitive) after the first occurrence
for counting purposes while retaining offsets of the first.
5. Sentence segmentation: spaCy sentencizer/parser; protect abbreviations (e.g., i.e., Fig., Eq.);
minimum sentence length 3 tokens.
6. Tokenization: spaCy tokenizer; hyphenated compounds kept as one token when both sides
alphabetic (k-means, decision-tree becomes decision tree lemma key).
7. Lemmatization: spaCy lemmatizer; lowercased lemma used for keys (trees to tree); original
surface form retained for display.
8. Stopword removal: spaCy list plus NLTK English stopwords plus academic filler list (chapter,
figure, table, example, following, shown, using, also, however). Stopwords are dropped as single
candidates and never allowed at phrase edges; internal stopwords allowed only for the pattern noun
of noun in P2.
9. Punctuation handling: removed from candidates except internal hyphens, apostrophes in words,
and + # . inside known tokens (C++, C#, .NET, Node.js).
10. Number handling: pure numbers dropped; alphanumeric technical tokens kept (1NF, 2NF, 3NF,
BCNF, IPv6, H2O). Years dropped.
2.2 Sectioning
Sections are detected before preprocessing. Heading heuristics: a line is a heading if it is <= 12
words, has no terminal period, and (is ALL CAPS, or Title Case, or starts with a numbering pattern such
as 1., 1.2, Chapter 3, Unit II). Sections shorter than 80 tokens merge with the previous section;
sections longer than 1,200 tokens are split by the long-document procedure (Section 15). If no
headings exist, the document is windowed.

3. N-grams
An n-gram is a contiguous sequence of n tokens. Unigrams capture single terms (algorithm), bigrams
two-word concepts (decision tree), trigrams three-word concepts (support vector machine, natural
language processing).
3.1 Generation
For every sentence, generate 1-, 2- and 3-grams over lemmas, keeping character offsets. Longer
n-grams are not generated because they rarely represent study concepts and inflate the candidate
space.

4. TF-IDF
Term frequency (TF) measures how often a candidate occurs in the document; inverse document
frequency (IDF) down-weights terms that are common across many sections or in general language;
TF-IDF is their product and highlights terms that are frequent here but not everywhere.
4.1 Formulas
 TF(t)       = 1 + ln(count(t))                      if count(t) > 0, else 0   (sublinear)
IDF_doc(t)  = ln( (1 + N) / (1 + df(t)) ) + 1       N = #sections, df = #sections containing t
IDF_bg(t)   = ln( (1 + M) / (1 + bg_df(t)) ) + 1    M = background corpus size (background_idf.json)
                                                    unseen terms receive the maximum IDF_bg
IDF(t)      = IDF_bg(t)                             if N < 5
            = 0.5 * IDF_doc(t) + 0.5 * IDF_bg(t)    if N >= 5
raw_tfidf(t)= TF(t) * IDF(t) * m(n)                 m(1)=1.00, m(2)=1.15, m(3)=1.25
tfidf_c(t)  = raw_tfidf(t) / max over candidates of raw_tfidf   (range 0..1)
4.2 Why TF-IDF
  Fast, deterministic, interpretable, no training or GPU needed.
 Works on a single document when combined with a background IDF table (built once from an open
general-English corpus and shipped as data/background_idf.json, about 50,000 terms).
 Weakness: cannot understand meaning or synonyms. This is why Phase 2 adds a semantic signal.
Implementation uses scikit-learn TfidfVectorizer with a custom analyzer that returns precomputed
candidate keys per section (so n-gram logic stays in ngram_extractor.py), norm=None, smooth_idf=True,
sublinear_tf=True; blended IDF is applied afterward.

5. Keyword Extraction
Keywords are distinctive vocabulary items shown as chips; topics are study concepts shown as
ranked cards. The two lists overlap but are produced separately.
 1. Start from all candidates after n-gram filters.
2. Rank by raw_tfidf(t) (already length-boosted).
3. Remove candidates whose surface form is a single generic word in the academic filler list.
4. Keep the top 30 keywords; report count and normalized score raw/max.
5. Per-topic keywords: for each topic, collect candidates co-occurring in the same sentences as the
topic; rank by co-occurrence count times TF-IDF; keep top 3 to 5 excluding the topic itself and its
sub-phrases.
Example. Input: Supervised learning uses labeled datasets to train machine learning models.
Keywords: Supervised Learning, Labeled Dataset, Machine Learning, Training, Models.

9. Semantic Embeddings (Phase 2)
Model: sentence-transformers/all-MiniLM-L6-v2 (384 dimensions, about 90 MB, CPU friendly). Pipeline:
text to tokens to transformer to pooled embedding vector; similarity is measured with cosine
similarity.
cos(a, b) = (a . b) / ( ||a|| * ||b|| )        range -1..1 (higher = more similar)
With L2-normalized vectors, cos(a, b) = a . b
 Embed each topic candidate string and each section (truncate to 256 word pieces; longer sections
are embedded by sentence groups and averaged).
 Document centroid: e_doc = normalize(mean(section embeddings)).
 Semantic relevance: semantic_c(t) = max(0, cos(e_t, e_doc)) / max_t(...).
 Relatedness example: Predicting categories versus Classification yields high cosine although
the words differ.
 Batch encode (batch size 32), torch.set_num_threads(2), model loaded once at startup, embeddings
cached per request.
 Fallback: if the model is unavailable, skip the stage, set semantic_enabled=false, renormalize
weights, and add warning SEMANTIC_DISABLED.

11. Topic Hierarchy (Phase 2)
Goal: assign each topic at most one parent so the result forms a forest with maximum depth 4.
11.1 Evidence Score
 e(p, c) = 0.40 * lex(p, c) + 0.30 * pat(p, c) + 0.30 * max(0, cos(e_p, e_c))
lex = 1.0 if tokens(p) is a proper subset of tokens(c)    (regression, linear regression)
      0.5 if head(p) == head(c) and generality(p) > generality(c)
      0.0 otherwise
pat = 1.0 if a sentence matches "p (includes|such as|consists of|types of|kinds of|
      comprises) ... c" or an enumeration under p, else 0.0
generality(t) = fraction of sections containing t   (parent needs generality >= child)
11.2 Algorithm
 1. Consider topic pairs among the top 40 topics; keep pairs with generality(p) >= generality(c), p !=
c.
2. For each topic c, choose the parent p with maximum e(p, c); require e >= 0.45 (configurable). Tie:
higher score.
3. Build a NetworkX DiGraph; detect cycles with find_cycle; remove the lowest-evidence edge in each
cycle until acyclic.
4. Clamp depth to 4 by re-attaching deeper nodes to their grandparent.
5. Topics without a parent are roots. Store parent_id, children_ids, depth.

15. Long-Document Processing
 1. Chunking: split by detected sections; any section over 1,200 tokens is split on sentence
boundaries into windows of about 800 tokens with 100-token overlap.
2. Per-chunk work: preprocessing and candidate extraction run per chunk in a loop (bounded
memory); embeddings batched.
3. Aggregation: occurrence counts and first positions are computed on global character offsets
so overlapped regions are never double-counted; section_ids unions; in_heading and in_definition
are OR-ed.
4. Deduplication: merge candidates with equal normalized key, acronym mappings, or (P2) cosine
>= 0.92; keep the most frequent surface form.
5. TF-IDF: df computed across chunks/sections (Section 4).
6. Limits: 150,000 characters; above 30,000 characters run as an asynchronous job (P2). Complexity
is linear in document length except clustering (quadratic in <= 60 topics).

16. Evaluation Methodology
16.1 Gold Dataset
Create backend/data/gold/ with at least 30 documents (10 computer science, 5 physics/chemistry, 5
biology, 5 humanities/social science, 5 mixed or noisy PDFs). For each, one author lists 8 to 20
expected topics; a second reviewer resolves disagreements. Store as JSON: {doc_id, source,
text_path, gold_topics: [{name, priority?}]}. Split 20 dev / 10 test; the test split is never used for
tuning.
16.2 Matching
A predicted topic matches a gold topic if their normalized lemma keys are equal, or token-set Jaccard
>= 0.6, or (for multi-word gold topics) the predicted key contains the gold key with >= 0.75 token
overlap. Each gold topic can be matched once.
16.3 Metrics
 Precision@K  = |TopK and Gold| / K                 (how many extracted topics are relevant)
Recall@K     = |TopK and Gold| / |Gold|            (how many important topics were found)
F1@K         = 2 * P@K * R@K / (P@K + R@K)       (balance)
TopK-Acc     = |TopK and Gold| / min(|Gold|, K)    (expected topics found within top K)
HIGH-Precision = fraction of HIGH topics that match gold topics
Report macro-averages over documents for K in {5, 10, 15}.
Example. Gold: Machine Learning, Classification, Regression. Output: Machine Learning, Classification,
Regression, Dataset, Prediction. P@5 = 3/5 = 0.60, R@5 = 3/3 = 1.00, F1@5 = 0.75.
